## Decisions

A decision marked **departs** differs from the ticket brief or the spike; Spud puts those to Eric.

1. `## Team` is one generated block: a stats table, the member tree carrying each member's "worked on / built" sentence, and `![[Fleet.base#Team]]`. **Departs:** the sentence sits on the tree line, not in a table column (§1.4).
2. Run is `spawned → stopped`, falling back to `finished` for rows with no stop, and shows only a measured duration. **Departs:** the brief says `spawned → finished` (§1.3).
3. Tokens are three figures, `out`, `in` and `cached`, from a run's transcript sum only; `total_tokens` is never shown. **Departs:** the brief's example is input plus output, and the spike has one `tokens` figure (§2).
4. "Worked on / built" takes the sources in the briefed order (summary, result, return_text) through one pipeline, cut at 400 characters on whole sentences. **Departs:** within a source, a paragraph that fails the status-line rule moves on to that source's next paragraph, so "first paragraph" becomes "first paragraph that reads as work" (§3).
5. Order: the lead's subtree first, then lineage order; every status is listed (§4).
6. The tree stays, but not for the graph: links in table cells already count for the graph and backlinks. It stays because it carries the sentences. **Departs:** the spike keeps the list for the graph (§5).
7. The Team view filters `ticket == this` (documented, and confirmed in the bundle), shows the run numbers with team totals, and needs five member frontmatter keys emitted only when known: `duration_ms`, `tool_uses`, `tokens_out`, `tokens_in`, `tokens_cached`. **Departs:** the spike's `tokens` becomes three keys plus `tool_uses`, and the view shows sums instead of parent, spawned and finished (§6).
8. `## Team` is derived from rows alone. Stored Team prose is no longer rendered; the importer turns a tree line's ` — text` into that member's summary and reads the new keys back; the acceptance tests change. **Departs:** from the importer's current rule of keeping Team prose the rows cannot regenerate (§8).
9. At merge Spud pastes the view, rewrites two templates and some prose, and backfills five imported members' summaries (§10).

## 1. The `## Team` section

### 1.1 Shape

For a ticket with at least one member, the section body is three blocks separated by one blank line:

```text
| Member | ID | Persona | Model | Status | Run | Tokens | Tools |
|---|---|---|---|---|---|---|---|
<one table row per member>

<one tree line per member>

![[Fleet.base#Team]]
```

`ticket_section_text(con, t, "Team")` returns exactly that, with no trailing newline; `body_with_sections` adds the blank line after it, as for every section. The header and delimiter lines are byte-exact as shown. A ticket with no members gets an empty section body, as today: no table, no tree, no embed.

### 1.2 Table cells

Rows follow §4's order. A row is `| ` + the eight cells joined with ` | ` + ` |`.

| Column | Cell | When there is nothing |
|---|---|---|
| Member | depth marker, then the folder-qualified link with an escaped pipe (below) | never empty |
| ID | `members.lineage` as stored | never empty |
| Persona | `persona`; for a contractor `` contractor on `agent_type` ``, today's `persona_label` | never empty |
| Model | the tier; when `resolved_model` is set, `tier (resolved_model)` | the tier alone |
| Status | the status word; `blocked` and `failed` in bold, `**failed**` | never empty |
| Run | §1.3 | `—` |
| Tokens | `<out> out · <in> in · <cached> cached` (§2) | `—` |
| Tools | `tool_uses` as a plain integer | `—` |

The Member cell at depths 1, 2 and 3:

```text
[[SPUD-001/Kestrel\|Kestrel]]
↳ [[SPUD-001/Huckleberry\|Huckleberry]]
↳↳ [[SPUD-001/Ozette\|Ozette]]
```

That is `↳` (U+21B3) repeated depth − 1 times and one space when depth is 2 or more, then `[[<team_key>/<name>\|<name>]]`. The escaped pipe is how Obsidian documents an alias inside a table: "If you want to use aliases … in your table, you need to add a `\` before the vertical bar" (Advanced formatting syntax, *Vertical bars in tables*); §5 shows the cached link still points at the member. Leading spaces in a cell are not rendered, so depth needs a visible character, and `↳` needs no HTML or entity. Depth 3 exists only in SPD-001's imported history; `max_depth` is 2.

Every cell built from data (persona label, model, resolved model) has `|` replaced by `\|`. None contains one today, but `resolved_model` comes from the harness. `—` (U+2014) alone in a cell means not recorded, which covers planned rows, imported rows and runs without usage.

### 1.3 Run

- A stamp is **unknown** when it is NULL, empty, shorter than 16 characters, or an imported minute-only stamp at midnight (16 characters ending in `T00:00`, SPD-001's Ozette placeholder). The hooks write seconds and an offset, so a real midnight spawn never has that shape.
- Start is `spawned_at`. An unknown start makes the whole cell `—`: planned rows, rows that failed before spawning, Ozette.
- End is `stopped_at` when known, else `finished_at` when known, else there is no end.
- Text:
  1. The start's `HH:MM` (characters 11 to 16 of the stamp, in the clock it was written in, never converted). Prefix it with `YYYY-MM-DD ` when the start's date (first 10 characters) differs from the ticket's `created_at` date.
  2. ` →`.
  3. When there is an end: a space and the end's `HH:MM`, prefixed with `YYYY-MM-DD ` when its date differs from the start's.
  4. When `duration_ms` is set: ` · ` and the duration.
- Duration: minutes = (ms + 30000) // 60000. Zero minutes is `<1 min`, fewer than 60 is `N min`, otherwise `H h` or `H h M min`.

Why the end is the stop, not the verdict: Run is the member's own run, and `duration_ms` measures spawn to return. `finished_at` is when the parent recorded its verdict, so it adds the parent's review time (Pompadour stopped at 20:36:51 and was finished at 20:41:50). An interval ending at the verdict would disagree with the duration printed beside it. Imported rows have neither `stopped_at` nor `duration_ms`, so they read `spawned → finished` with no duration.

| Row | Run |
|---|---|
| Pompadour, SPD-015 | `20:01 → 20:36 · 35 min` |
| Kestrel, SPD-001, imported | `12:25 → 12:31` |
| Ozette, SPD-001, `00:00` spawn | `—` |
| active, still running | `20:01 →` |
| returned, verdict not yet recorded | `20:01 → 20:36 · 35 min` |
| planned and never spawned, or failed before spawning | `—` |
| spawned 2026-09-13 on a ticket created 2026-09-12 | `2026-09-13 09:05 → 09:50 · 45 min` |
| a run across midnight | `23:50 → 2026-09-13 00:20 · 31 min` |

### 1.4 Why a table and a tree, not a summary column

- Eric reads ticket notes in reading view. `.obsidian/app.json` sets `"defaultViewMode": "preview"`, and every open note tab in `workspace.json` is in `preview` mode. Readable line length is not set, so the default applies, and the bundle's `app.css` sets `--file-line-width: 700px`.
- Reading-view tables get no width or scroll rule: `.markdown-rendered table` sets margins and `word-break: normal` only. Cells wrap (`--table-white-space: break-spaces`, `--table-column-min-width: 6ch`, `--table-column-max-width: none`). Only live preview puts a table in a horizontally scrolling widget (`.cm-table-widget { … overflow-x: auto }`).
- So a ninth column holding a 150 to 400 character paragraph shares 700 px with eight others. Every row becomes a tall, narrow stack of wrapped words, and short cells like `20:01 → 20:36 · 35 min` wrap too. On a tree line the same sentence gets the full width, reads as a sentence, and sits under its parent.

The table answers who, as what, on which model and how it went; the tree answers what each member worked on and built. The ticket's Done-when asks that "the summary column reads as a sentence about the work": that sentence is kept, and moves out of the column.

### 1.5 The member tree

One line per member, in table order:

```text
<two spaces × (depth − 1)>- [[<team_key>/<name>|<name>]] (<lineage>, <persona label>, <tier>)[ — <worked on / built>]
```

Up to the closing parenthesis this is today's `team_line` with today's indentation. When §3 yields text, the line continues with ` — ` (space, U+2014, space) and the text; when §3 yields nothing, the line ends at the parenthesis, exactly today's line. The pipe is not escaped: a list line is not split on `|`.

### 1.6 The embed

`![[Fleet.base#Team]]` alone on the last line of the section. Obsidian: "To specify the default view for an embed use `![[File.base#View]]`" (Views, *Embed a view*). It comes last because the table and the tree are the card. The view is the live, sortable copy of the numbers with team totals, and it is visually heavy (a toolbar and its own table), so it should not sit between the stats and the sentences.

## 2. Tokens, honestly

What the columns hold today:

- `usage_json` has two shapes.
  - `transcript_usage`, at `SubagentStop`, stored `{"source": "transcript", "messages": N, "usage": {input_tokens, output_tokens, cache_creation_input_tokens, cache_read_input_tokens}}` summed over every assistant message in the member's own transcript. Since [[SPD-023]] the sum instead groups the transcript's assistant entries by request (`message.id` with its `requestId`) and counts each request once, by its last entry: the harness writes one JSONL entry per content block, and every entry of a request repeats that request's usage with only `output_tokens` growing. Tool uses count distinct `tool_use` block ids, `messages` counts requests, and the sum now carries a `"counting": "request"` marker; a sum stored before carries none and ran four to five times too high, which `spud member resum` re-sums from the member's transcript.

This isn't a total across the whole run", and notes that "`totalTokens` and `usage` cover the final request only"; `totalDurationMs` and `totalToolUseCount`, whole-run figures by the same reference, now fill `duration_ms` and `tool_uses`.

The card's three figures, taken from `usage_json` only when it parses to an object with `"source": "transcript"` and a `usage` object:

| Figure | Formula | Meaning |
|---|---|---|
| out | `output_tokens` | what the member wrote |
| in | `input_tokens + cache_creation_input_tokens` | input read fresh: each request's uncached tail plus what was written into the cache |
| cached | `cache_read_input_tokens` | input re-read from the prompt cache |

On 2026-09-12 Pompadour read `161k out · 2.9M in · 44.3M cached` and Sarpo `122k out · 2.6M in · 22.2M cached`; since [[SPD-023]]'s re-sum, Pompadour reads `160k out · 711k in · 11.8M cached` and Sarpo `121k out · 464k in · 5.4M cached`.

1. n < 1,000: `n`.
2. tenths = (10n + 500) // 1,000. If tenths < 100: `<tenths // 10>.<tenths % 10>k`.
3. k = (n + 500) // 1,000. If k < 1,000: `<k>k`.
4. tenths = (10n + 500,000) // 1,000,000. If tenths < 10,000: one decimal and `M`.
5. Otherwise the same step in billions, with `B`.

| n | shown |
|---|---|
| 0, 999, 1000 | `0`, `999`, `1.0k` |

## 3. Worked on / built

### 3.1 Sources

`members.summary`, then `members.result`, then `members.return_text`. Each goes through §3.2, and the first to yield text wins. No source is exempt: a parent's summary that is only a status line falls through too. When no source yields text, the tree line gets no suffix.

### 3.2 The pipeline for one source

1. NULL or empty yields nothing.
2. Replace `\r\n` with `\n`, then delete every HTML comment, `<!-- … -->`, matched non-greedily across lines. Every imported Result opens with a template comment.
3. Split the text into blocks (a CommonMark-shaped subset). Only paragraphs are candidates. A blank line (whitespace only) ends any block.

   | Block | Starts with (after up to 3 spaces) | Runs to |
   |---|---|---|
   | fence | ```` ``` ```` or `~~~` (3 or more) | a line of the same character at least as long, or the end |
   | heading | 1 to 6 `#`, then a space or end of line | its own line; a paragraph whose next line is only `=` or only `-` is a setext heading, both lines |
   | thematic break | `---`, `***` or `___`, spaced or not, alone on the line (checked before list items) | its own line |
   | list | `-`, `+`, `*`, or 1 to 9 digits and `.` or `)`, then a space or end of line | the next blank line |
   | quote | `>` | the last consecutive line starting with `>` |
   | table | the pipe character | the last consecutive line starting with it |
   | paragraph | anything else | a blank line, or the line before one that opens a fence, heading, quote, table, thematic break or list item |

4. Join each paragraph's lines with single spaces, collapse whitespace runs to one space, and trim.
5. **Label.** A paragraph may open with a label, bold or plain.
   - **Bold:** `**…**` or `__…__` holding 1 to 60 characters and 1 to 6 words, with no `*` or `_` inside. It counts as a label only when a `.` or `:` ends it: inside the markers, right after them, or after a parenthetical that follows them (`**Produced** (branch …, uncommitted):`). Whitespace must follow. Without that punctuation a bold opening is emphasis and is kept.
   - **Plain:** a capitalised word, up to four more words of letters, then `:` and whitespace (`Verified: `).

   Take the label, remove trailing `.` or `:`, and lowercase it. If it equals a stop label, or starts with one followed by a space, skip the paragraph. The stop labels are: verified, verification, tests, test observations, left, next, status, handoff, handoffs, team, decisions, open question, open questions, proposal, proposals, prose for spud, method note, sources, evidence, note, notes. Otherwise remove the label, with its parenthetical, and continue with the rest of the paragraph.
6. **Status-line rule.** Trim the rest; skip the paragraph if it is empty. Otherwise build a test form: remove backticks and `*`, trim, lowercase. The kept text is unchanged. Skip the paragraph when the test form matches any of:
   - **a.** It starts with a status word followed by a word boundary: `done`, `accepted`, `complete`, `completed`, `finished`, `ready`, `nothing further`, `nothing left`, `nothing else`, `nothing to do`, `no proposals`, `no open questions`, `no blockers`, `no changes`, `all done`, `all green`, `result recorded`.
   - **b.** It says where the work sits: optionally `produced`, `built`, `changed`, `written`, `delivered`, `committed` or `pushed` plus whitespace, then `on` or `in`, an optional `the`, then `worktree` or `branch`.
   - **c.** It opens with a member handle: `spud-<digits>/<name> (<lineage>, `.
   - **d.** It ends with `:`, so it introduces a list or block rather than saying anything.
   - **e.** Fewer than three words of prose remain once code spans, wikilinks and markdown links are removed. A word is a letter followed by letters, apostrophes or hyphens.
7. Strip trailing backslashes, then trailing whitespace. A backslash at the end of a list line would be a hard break.
8. Cut to 400 characters (§3.3). The result is the text.

### 3.3 The cut

Length is counted in characters (Python code points), markdown included.

- **At most 400:** unchanged.
- **Otherwise:** keep the longest prefix that ends at a sentence end and has at most 400 characters. No ellipsis: it is whole sentences.
- **A sentence end** is `.`, `!` or `?` plus any of `)`, `]`, `"`, `'`, `’`, `”`, `*` or `_` directly after it, followed by whitespace or the end of the text. It does not count inside a code span, a wikilink or a markdown link, nor when the next non-space character is a lowercase letter (as in `e.g. the`).
- **No sentence end fits:** cut inside the sentence. Start at index 399. While that index is strictly inside a code span, wikilink or markdown link, move it to the span's start. Then move back to the last space at or before it. Strip trailing spaces, commas, semicolons, colons, dashes and hyphens, then append `…` (U+2026). The result has at most 400 characters and never ends inside a span.

### 3.4 From markdown to a tree line

The text is always one line, because step 4 turns every newline into a space. Pipes stay as written; the text never enters a table cell. Links, code spans and emphasis stay, and render. Bullets never appear, because list blocks are never candidates. One known limit, left alone: a word written with a leading `#` in prose renders as a tag.

### 3.7 What a parent writes in `--summary` from now on

One or two sentences, 150 to 350 characters, past tense. Say what the member built or changed and where, with at most one clause of proof (tests, probes). No verdict ("Accepted", "Done"), no location or commit state ("on branch …, uncommitted"), no lists or line breaks. It is the line Eric reads on the ticket, so it names the artifact, not the process.

Example from [[SPD-015]], Pompadour's summary as recorded: "Extended the SubagentStop hold below Spud: a member is held once when a child of its own returned unrecorded or is still alive, with the exact command per child, and the childless message unchanged. 13 red-first tests (suite 220 green), three haiku probes showing the orphan under the old code and the hold, the recording and the release under the new one."

## 4. Order

Sort members by `lineage` as a string; zero-padded lineage sorts as a tree (`01`, `01.01`, `01.01.01`, `01.02`, `02`). When `tickets.lead_id` names a member, first come the members whose first lineage segment equals the lead's (the lead's subtree), then the rest, each group in lineage order.

`member new` makes the first root member ever planned the lead and never changes it. That member is always `01`, so for every ticket the CLI made, this is plain lineage order. Only an imported ticket could name another lead: with lead `02` the order is `02, 02.01, 01, 01.01`; with no lead, `01, 01.01, 02, 02.01`.

Every status is listed (planned, active, done, blocked, failed); nothing is filtered or hidden. The tree uses the same order.

## 5. The tree list, the graph and backlinks

**Links in table cells count.** In the 1.13.7 bundle, the markdown worker that feeds the metadata cache parses `[[…]]` into `ilink` nodes. It takes each target from a splitter that cuts at the first `|` and then drops a trailing backslash, `e.endsWith("\\")&&(e=e.substring(0,e.length-1))`, in `worker.js` and again as `$E` in `app.js`. So `[[SPUD-015/Pompadour\|Pompadour]]` is cached as a link to `SPUD-015/Pompadour` with display text `Pompadour`. From there:

- the cache turns those references into `resolvedLinks` (`resolveLinks`);
- backlinks come from the same references (`getBacklinksForFile`);
- the rename updater keeps the escape when it rewrites such a link (`/\\\|/.test(r)?"\\|":"|"`).

Obsidian's own help uses the pattern inside a table: the Views page lists `[[Table view\|Table]]`.

**Decision.** The tree is not needed for the graph, because the table already draws the ticket-to-member edges. It stays because it is where the sentences read well, nested by depth. ## 6. The Fleet.base Team view

### 6.1 The filter

The filter is `ticket == this`, as a view-level filter.

- **Docs, Bases syntax, *Access properties with this*:** "When the base is embedded in another file, `this` points to properties of the _embedding_ file".
- **Docs, Bases syntax, *Files and links*:** "Links can be compared to files such as `file` or `this`. They will equate if the link resolves to the file. For example, `author == this`." Member notes carry `ticket: "[[SPD-nnn]]"`, which Bases reads as a Link ("Wikilinks in frontmatter properties are automatically recognized as Link objects", same section).
- **Bundle:** `this` is built from the embed's own file: `case"this":var t=this.ctx.local;return t?new GX(this.app,t.file,t)`. `GX` is the `ThisFile` value and extends the File value `kK` (`t.type="ThisFile",t}(kK)`). `==` is loose equality: `case"==":return new uK(iK.looseEquals(o,a))`. For a Link compared with a File, `looseEquals` is `e instanceof kK&&this.resolve()===e.file`, where `resolve()` calls `metadataCache.getFirstLinkpathDest`. So `ticket == this` holds exactly when the member's `ticket` link resolves to the embedding note.
- **`ticket.linksTo(this)`** would also work. The bundle's `linksTo` is `getFirstLinkpathDest(e.data,"")===t.file`, the same resolution, despite the Functions page's wording "has a link to `file`". It is longer, so it is not used.
- **Wrong:** `file.hasLink(this.file)` also matches any member note whose body links the ticket, including other teams' members. `this.file.hasLink(file)` also matches every member the ticket note links to, including proposers on other teams.
- **Global filters still apply** (`file.hasTag("spudagent")`, not in `ledger/_templates`). Global and view filters "will be concatenated with an `AND`" (Bases syntax, *Filters*).
- **Opened on its own**, `Fleet.base` points `this` at the base file ("When the base is opened in main content area, `this` points to properties of the base file itself"), so its Team tab lists nothing. The view is meant to be embedded.

## Reference implementation

This is specification, not code to paste. It is the core of the scratch prototype that produced every mock and vector above. `m` is a `members` row and `t` a `tickets` row. Names are suggestions; behaviour is not.

```python
import json
import re

DASH, ARROW, DOT, HOOK, ELLIPSIS = "—", "→", "·", "↳", "…"
CAP = 400


# -- numbers and stamps --------------------------------------------------------

def humanize(n):
    if n < 1000:
        return str(n)
    tenths = (n * 10 + 500) // 1000
    if tenths < 100:
        return "%d.%dk" % (tenths // 10, tenths % 10)
    k = (n + 500) // 1000
    if k < 1000:
        return "%dk" % k
    tenths = (n * 10 + 500_000) // 1_000_000
    if tenths < 10_000:
        return "%d.%dM" % (tenths // 10, tenths % 10)
    tenths = (n * 10 + 500_000_000) // 1_000_000_000
    return "%d.%dB" % (tenths // 10, tenths % 10)


def duration(ms):
    if ms is None:
        return None
    minutes = (ms + 30_000) // 60_000
    if minutes == 0:
        return "<1 min"
    if minutes < 60:
        return "%d min" % minutes
    h, m = divmod(minutes, 60)
    return "%d h" % h if m == 0 else "%d h %d min" % (h, m)


def known(stamp):
    """None for NULL, empty, a stamp with no time, or an imported minute-only stamp at 00:00."""
    if not stamp or len(stamp) < 16 or (len(stamp) == 16 and stamp.endswith("T00:00")):
        return None
    return stamp


def run_cell(m, ticket_created):
    start = known(m["spawned_at"])
    if start is None:
        return DASH
    text = start[11:16] if start[:10] == ticket_created[:10] else start[:10] + " " + start[11:16]
    text += " " + ARROW
    end = known(m["stopped_at"]) or known(m["finished_at"])
    if end:
        text += " " + (end[11:16] if end[:10] == start[:10] else end[:10] + " " + end[11:16])
    d = duration(m["duration_ms"])
    if d:
        text += " %s %s" % (DOT, d)
    return text


def token_counts(usage_json):
    """out, in and cached from a transcript sum; None for any other source or shape."""
    if not usage_json:
        return None
    try:
        u = json.loads(usage_json)
    except ValueError:
        return None
    if not isinstance(u, dict) or u.get("source") != "transcript" or not isinstance(u.get("usage"), dict):
        return None
    vals = {}
    for k in ("input_tokens", "output_tokens", "cache_creation_input_tokens", "cache_read_input_tokens"):
        v = u["usage"].get(k, 0)
        if isinstance(v, bool) or not isinstance(v, int) or v < 0:
            return None
        vals[k] = v
    return {"out": vals["output_tokens"], "in": vals["input_tokens"] + vals["cache_creation_input_tokens"],
            "cached": vals["cache_read_input_tokens"]}


# -- table cells, order, frontmatter ----------------------------------------------

def persona_label(m):  # today's, unchanged
    return "contractor on `%s`" % m["agent_type"] if m["persona"] == "contractor" else m["persona"]


def esc(text):
    return str(text).replace("|", "\\|")


def table_row(t, m):
    marker = (HOOK * (m["depth"] - 1) + " ") if m["depth"] > 1 else ""
    c = token_counts(m["usage_json"])
    cells = [
        "%s[[%s/%s\\|%s]]" % (marker, t["team_key"], m["name"], m["name"]),
        m["lineage"],
        esc(persona_label(m)),
        esc(m["model"] + (" (%s)" % m["resolved_model"] if m["resolved_model"] else "")),
        "**%s**" % m["status"] if m["status"] in ("blocked", "failed") else m["status"],
        run_cell(m, t["created_at"]),
        "%s out %s %s in %s %s cached" % (humanize(c["out"]), DOT, humanize(c["in"]), DOT, humanize(c["cached"])) if c else DASH,
        str(m["tool_uses"]) if m["tool_uses"] is not None else DASH,
    ]
    return "| " + " | ".join(cells) + " |"


def ordered(rows, lead_id):
    rows = sorted(rows, key=lambda m: m["lineage"])
    lead = next((m for m in rows if m["id"] == lead_id), None)
    if lead is None:
        return rows
    root = lead["lineage"].split(".")[0]
    return [m for m in rows if m["lineage"].split(".")[0] == root] + [m for m in rows if m["lineage"].split(".")[0] != root]


def usage_pairs(m):
    """render_member's extra pairs, after finished and before tags; each only when known."""
    pairs = []
    if m["duration_ms"] is not None:
        pairs.append(("duration_ms", ("plain", m["duration_ms"])))
    if m["tool_uses"] is not None:
        pairs.append(("tool_uses", ("plain", m["tool_uses"])))
    c = token_counts(m["usage_json"])
    if c:
        pairs += [("tokens_out", ("plain", c["out"])), ("tokens_in", ("plain", c["in"])), ("tokens_cached", ("plain", c["cached"]))]
    return pairs


# -- worked on / built ------------------------------------------------------------

FENCE = re.compile(r"^ {0,3}(`{3,}|~{3,})")
HEADING = re.compile(r"^ {0,3}#{1,6}(\s|$)")
RULE = re.compile(r"^ {0,3}([-*_])( *\1){2,} *$")
SETEXT = re.compile(r"^ {0,3}(=+|-+) *$")
ITEM = re.compile(r"^ {0,3}([-+*]|\d{1,9}[.)])(\s|$)")
QUOTE = re.compile(r"^ {0,3}>")
TABLE = re.compile(r"^ {0,3}\|")
COMMENT = re.compile(r"<!--.*?-->", re.S)


def blocks(text):
    lines = text.split("\n")
    out, i = [], 0
    while i < len(lines):
        line = lines[i]
        if not line.strip():
            i += 1
            continue
        f = FENCE.match(line)
        if f:
            close = re.compile(r"^ {0,3}%s{%d,} *$" % (re.escape(f.group(1)[0]), len(f.group(1))))
            j = i + 1
            while j < len(lines) and not close.match(lines[j]):
                j += 1
            out.append(("fence", lines[i : j + 1]))
            i = j + 1
            continue
        if HEADING.match(line):
            out.append(("heading", [line]))
            i += 1
            continue
        if RULE.match(line):
            out.append(("rule", [line]))
            i += 1
            continue
        for kind, rx in (("list", ITEM), ("quote", QUOTE), ("table", TABLE)):
            if rx.match(line):
                j = i + 1
                while j < len(lines) and lines[j].strip() and (kind == "list" or rx.match(lines[j])):
                    j += 1
                out.append((kind, lines[i:j]))
                i = j
                break
        else:
            j, kind = i + 1, "paragraph"
            while j < len(lines):
                nxt = lines[j]
                if not nxt.strip() or FENCE.match(nxt) or HEADING.match(nxt) or QUOTE.match(nxt) or TABLE.match(nxt):
                    break
                if SETEXT.match(nxt):
                    kind, j = "heading", j + 1
                    break
                if RULE.match(nxt) or ITEM.match(nxt):
                    break
                j += 1
            out.append((kind, lines[i:j]))
            i = j
    return out


STOP_LABELS = ("verified", "verification", "tests", "test observations", "left", "next", "status", "handoff", "handoffs",
               "team", "decisions", "open question", "open questions", "proposal", "proposals", "prose for spud",
               "method note", "sources", "evidence", "note", "notes")
BOLD_LABEL = re.compile(r"^(\*\*|__)(?P<label>[^*_]{1,60}?)(?P<p1>[.:])?\1(?P<p2>[.:])?(?:\s*\((?P<paren>[^()]*)\)(?P<p3>[.:]))?\s+")
PLAIN_LABEL = re.compile(r"^(?P<label>[A-Z][A-Za-z]*(?: [A-Za-z]+){0,4}):\s+")
STATUS_START = re.compile(r"(done|accepted|complete|completed|finished|ready|nothing (further|left|else|to do)"
                          r"|no (proposals|open questions|blockers|changes)|all (done|green)|result recorded)\b")
WHERE_START = re.compile(r"((produced|built|changed|written|delivered|committed|pushed)\s+)?(on|in)\s+(the\s+)?(worktree|branch)\b")
HANDLE = re.compile(r"spud-\d+/\S+ \(\d+(\.\d+)*, ")
CODE = re.compile(r"`[^`]*`")
WIKILINK = re.compile(r"\[\[[^\]]*\]\]")
MDLINK = re.compile(r"\[[^\]]*\]\([^)]*\)")


def label_of(text):
    m = BOLD_LABEL.match(text)
    if m and 1 <= len(m.group("label").split()) <= 6 and (m.group("p1") or m.group("p2") or m.group("p3")):
        return m.group("label").strip().rstrip(".:").strip(), text[m.end():]
    m = PLAIN_LABEL.match(text)
    if m:
        return m.group("label"), text[m.end():]
    return None, text


def is_stop(label):
    low = label.lower()
    return any(low == s or low.startswith(s + " ") for s in STOP_LABELS)


def is_status_line(text):
    test = text.replace("`", "").replace("*", "").strip().lower()
    if STATUS_START.match(test) or WHERE_START.match(test) or HANDLE.match(test) or test.endswith(":"):
        return True
    rest = MDLINK.sub(" ", WIKILINK.sub(" ", CODE.sub(" ", text)))
    return len(re.findall(r"[A-Za-z][A-Za-z'’-]*", rest)) < 3


def spans(text):
    return [(m.start(), m.end()) for rx in (CODE, WIKILINK, MDLINK) for m in rx.finditer(text)]


def sentence_ends(text):
    protected = spans(text)
    ends = []
    for m in re.finditer(r"[.!?][)\]\"'’”*_]*(?=\s|$)", text):
        if any(a <= m.start() < b for a, b in protected):
            continue
        after = text[m.end():].lstrip()
        if after and after[0].islower():
            continue
        ends.append(m.end())
    return ends


def cut(text):
    if len(text) <= CAP:
        return text
    fits = [e for e in sentence_ends(text) if e <= CAP]
    if fits:
        return text[: max(fits)].rstrip()
    protected = spans(text)
    i, moved = CAP - 1, True
    while moved:
        moved = False
        for a, b in protected:
            if a < i < b:
                i, moved = a, True
    j = text.rfind(" ", 0, i + 1)
    i = j if j > 0 else i
    return text[:i].rstrip(" ,;:—–-") + ELLIPSIS


def first_paragraph(source):
    if not source:
        return None
    text = COMMENT.sub("", source.replace("\r\n", "\n"))
    for kind, lines in blocks(text):
        if kind != "paragraph":
            continue
        flat = re.sub(r"\s+", " ", " ".join(l.strip() for l in lines)).strip()
        label, rest = label_of(flat)
        if label is not None and is_stop(label):
            continue
        rest = rest.strip()
        if not rest or is_status_line(rest):
            continue
        return cut(rest.rstrip("\\").rstrip())
    return None


def worked_on(m):
    for column in ("summary", "result", "return_text"):
        text = first_paragraph(m[column])
        if text:
            return text
    return None


# -- the section -----------------------------------------------------------------

def team_line(team_key, m):  # today's, unchanged
    return "- [[%s/%s|%s]] (%s, %s, %s)" % (team_key, m["name"], m["name"], m["lineage"], persona_label(m), m["model"])


def team_section(t, rows):
    if not rows:
        return ""
    rows = ordered(rows, t["lead_id"])
    out = ["| Member | ID | Persona | Model | Status | Run | Tokens | Tools |", "|---|---|---|---|---|---|---|---|"]
    out += [table_row(t, m) for m in rows]
    out.append("")
    for m in rows:
        text = worked_on(m)
        out.append("  " * (m["depth"] - 1) + team_line(t["team_key"], m) + (" %s %s" % (DASH, text) if text else ""))
    out.append("")
    out.append("![[Fleet.base#Team]]")
    return "\n".join(out)
```
