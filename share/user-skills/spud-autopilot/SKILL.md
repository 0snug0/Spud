---
name: spud-autopilot
description: Work one Spud project's open tickets as {{identity_name}} in batches, each group of tickets that change the same files or the same feature folded into one main ticket and landed as one pull request or merge, in board order, until none is left or {{owner_name}} says stop. Only when {{owner_name}} types /spud-autopilot in that project's main checkout.
argument-hint: "[project]"
disable-model-invocation: true
---
You are working through one project's tickets as {{identity_name}}. The project key is `$ARGUMENTS`, which may be empty. In these steps `spud …` means `python3.14 -I -S {{launcher}} …`.

1. Read {{home}}/CLAUDE.md in full, then {{home}}/spud.config.json, with the Read tool: never cat or another shell command, because the Bash tool cuts its output at about 30,000 characters. They bind you from now on. Run `spud --as spud session claim`. If it refuses, quote the refusal, say this session is not {{identity_name}}, and stop. Then run the session ritual of CLAUDE.md from step 2.
2. The project is `$ARGUMENTS` when that is not empty, else the one `spud session show` names. If there is none, or `spud project list` has no project by that key, print that list, say which key was not found, and stop. This session must have been launched in that project's main checkout (`spud session show` prints its checkout as `root`); anywhere else, the home or a worktree included, say to launch Claude Code in the root `spud project show <key>` prints and type /spud-autopilot there, and stop. Work on no other project.
3. {{owner_name}} typed /spud-autopilot in this session, which asks for every group this run finishes to be landed: each merge and pull-request merge below is that request. The rule of CLAUDE.md on the auto-mode classifier still stands: a refused merge is never retried, rephrased or reached another way. Record the green pull request in the main ticket's Outcome, tell {{owner_name}} it is ready, and go on to the next group while that one waits.
4. Loop:
   1. Group. Re-read the board: `spud board --project <key>`. Take every open ticket that is not parked. Skip a ticket another session holds (live members this session did not spawn, `spud card <KEY>`, or a worktree another session works in), and say which you skipped and why. Read each one's brief (`spud ticket show <KEY>`) and `git grep` the files, modules and features it names. Tickets that change the same files or modules, or the same feature, form a group; a ticket that fits no group is a group of one. A group's main ticket is its highest-priority one, then its lowest-numbered. Take the group whose main ticket comes first in board order: priority, then active before queued, then number. Say the group in one line: its main ticket and the keys folded into it.
   2. Fold. In a group of more than one, `spud --as spud ticket edit <MAIN> --brief @-` adds each folded ticket's ask, under its key, to the main ticket's brief, and `ticket edit <MAIN> --sizing @-` names every folded key. The folded tickets stay open and unchanged until the batch lands, so nothing is lost if it fails. They get no members and no worktree of their own: they share the main ticket's, which its first `member new` binds, since a worktree may carry several tickets.
   3. Set the session title to `<MAIN> - <title>`.
   4. Work the main ticket by the full protocol of CLAUDE.md: activate it, `EnterWorktree` named `<main>-<slug>` (its key lower-cased), plan its members with briefs covering every folded ask, spawn them, and record every return before anything else. Verify once for the batch, never once per ticket: members verify by the project's own CLAUDE.md (`--changed` or its equivalent), and landing runs the full suite or the required checks once, on the tree that lands.
   5. A folded ask that turns out not to fit (it conflicts with another, needs {{owner_name}}, or is too large for the batch) goes back to its own ticket and never blocks the group: take it out of the main ticket's brief and sizing with `ticket edit`, and leave that ticket open for a later group.
   6. Land the group as one change by the project's `landing`, its title and every commit message naming every ticket in the group. `pr`: one ready pull request, `spud --as spud pr record --ticket <MAIN> --url <URL> --branch <head>` right after `gh pr create`, wait for the required checks, then `gh pr merge`. `merge`: the merge landing of CLAUDE.md, with the full suite once on the tree that merges. Leave the worktree with `ExitWorktree` (keep) if the landing has not; a pull request still waiting on {{owner_name}} leaves its worktree and every ticket of the group open. Once the change has merged, remove the worktree and delete its branch by the rules of CLAUDE.md, and run the sync the project's CLAUDE.md says the change needs. Then the tickets: `ticket edit <MAIN> --outcome` with the pull request or merge, and `spud --as spud ticket move <MAIN> --status done --next "…"`; for each folded ticket, `ticket edit <KEY> --outcome "landed in <PR or merge> with <MAIN>"` and `ticket move <KEY> --status done`, moving a queued one to `--status active` first, since the state machine has no move from queued to done.
   7. Say in one line: the group, its pull request or merge, and what landed. Then go round again from the board, which may have changed: group what is left afresh.
5. Stop when no open ticket you may take is left; when {{owner_name}} says stop (record the current member's return first, and leave an unlanded worktree in place, saying where it is and which group it holds); or when this session's context is near its end (say where the run stopped and which group is next).
6. A blocked member, a failing suite or a merge conflict: ask {{owner_name}} with AskUserQuestion (up to four questions, each with your recommendation) and wait. If the answer is to defer it, `ExitWorktree` (keep), park the main ticket with the reason (`spud --as spud ticket move <MAIN> --status parked --reason "…"`), leave its folded tickets open, and go on to the next group.
7. At the end, a summary: each group worked (its main ticket and folded keys) and how it ended (landed, waiting on a merge, parked), each ask sent back to its own ticket, and what is left on the board.
