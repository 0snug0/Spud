# SPD-009 — Protocol edits in Spud's own files for the CLI era

## Brief
`CLAUDE.md`, `.claude/agents/spudagent.md`, `ledger/_templates/ticket.md`, `ledger/_templates/spudagent.md` and the brief template describe file edits, `date`, and counting files. Once [[SPD-007]] and [[SPD-008]] land they must describe `spud` commands instead: the qualified description `SPUD-nnn/Name (id, persona)`; `run_in_background: true` as the default for every spudagent spawn; deliverable globs recorded at `spud member new`; the absolute CLI path; the `permissions.allow` rule for the CLI (background subagents cannot answer prompts); the finishing rule that `SubagentStop` holds a child for (Result or Blocked through the CLI before returning); the `planned` member status. Evidence: the mapping section of the spike; CLAUDE.md protocol steps 1 to 7.

Waits on Eric's answers to open questions 3, 5 and 6. Lands with [[SPD-007]] and [[SPD-008]].

Done when: the three documents and the templates agree with the CLI, and a ticket run after the cutover shows a team that used only `spud` commands.

## Size, persona and model decision
No spudagent: every deliverable is a Spud-owned file, which Law 1 reserves to Spud, edited when Eric says go. Same shape as [[SPD-003]].
