# SPD-009 — Protocol edits in Spud's own files for the CLI era

## Brief
`CLAUDE.md`, `.claude/agents/spudagent.md`, `ledger/_templates/ticket.md`, `ledger/_templates/spudagent.md` and the brief template describe file edits, `date`, and counting files. Once [[SPD-007]] and [[SPD-008]] land they must describe `spud` commands instead: the qualified description `SPUD-nnn/Name (id, persona)`; `run_in_background: true` as the default for every spudagent spawn; deliverable globs recorded at `spud member new`; the absolute CLI path; the `permissions.allow` rule for the CLI (background subagents cannot answer prompts); the finishing rule that `SubagentStop` holds a child for (Result or Blocked through the CLI before returning); the `planned` member status. Evidence: the mapping section of the spike; CLAUDE.md protocol steps 1 to 7.

Decided by Eric, 2026-09-12: fan-out limits count children alive at once, so "up to N sub-agents" becomes "up to N alive at once" and a finished or failed child frees its slot (question 3); descriptions carry the team key and background is the spawn default (question 5); refusals from day one (question 6). Lands with [[SPD-007]] and [[SPD-008]].

Done when: the three documents and the templates agree with the CLI, and a ticket run after the cutover shows a team that used only `spud` commands.

Inputs from [[SPD-008]] (Desiree's Result, 2026-09-12): the canonical form is `spud --as <agent_id> member result|log|block …` (`--as` and `--json` are accepted anywhere; the hold and the Stop reason use this order); the first allow reserves a planned row, so after a harness-failed spawn the parent finishes that row as failed and plans a new one, never re-issuing the same description; `SessionStart` matchers stay `startup|resume|compact`, and the docs now also list `clear` and `fork`, decide whether they get the board; the `MultiEdit` matcher is kept although 2.1.269's tool list no longer shows the tool; `settings sync` writes `Bash(python3.14 -I -S <home>/bin/spud *)`, `Bash(<sys.executable> -I -S <home>/bin/spud *)` and `Bash(<home>/bin/spud *)`, and `permissions.allow` in a project settings file is ignored until the folder is trusted while the hook's own allow is not; the harness refuses, from a worktree session, both `git -C <main checkout>` and Write-tool writes to shared-checkout paths ("edit the worktree copy instead"), so the recipe becomes: ledger commits on `main` before `EnterWorktree` or after `ExitWorktree keep`, and no spudagent writes a ledger file at all once the CLI is the ledger.

## Size, persona and model decision
No spudagent: every deliverable is a Spud-owned file, which Law 1 reserves to Spud, edited when Eric says go. Same shape as [[SPD-003]].

Model: Eric first asked for opus (2026-09-12, weekly Fable budget about half used), then, since a session cannot switch its own model, said to continue on fable for now; Spud runs this ticket on **fable**.
