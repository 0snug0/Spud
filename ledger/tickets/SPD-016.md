# SPD-016 — Hook follow-ups: slimmer entry point, native Agent deny rules, worktrees outside .claude/worktrees

## Brief
Three small hardenings Desiree proposed on [[SPD-008]], grouped because one engineer does them in one worktree:

1. **Latency.** Each hook call costs about 60 ms (median of 15 runs each of `PreToolUse(Bash)`, `SessionStart`, `Stop`) against the spike's 18 ms, because `bin/spud` is a 4,400-line suffix-less script compiled on every run under `-I -S`, plus its imports. A slimmer entry point for the hook path (a cached module, or lazy imports) should bring it near 20 ms without a second copy of the logic. Measure before and after.
2. **Native deny rules.** Today's permissions docs document `Agent(isolation:*)` and `Agent(model:…)` parameter rules. `spud settings sync` should also write `permissions.deny` entries for `Agent(isolation:*)` and `Agent(model:inherit)`, so Law 3 holds even if the hook is removed or fails to run. Merge like the allow rules: keep foreign entries, idempotent, dry run.
3. **Worktrees elsewhere.** The path rule maps only `<home>` and `<home>/.claude/worktrees/<name>/` to repository-relative paths; a worktree created elsewhere (`git worktree add ../x`) counts as outside every project root, where writes are allowed. Map every worktree that `git worktree list --porcelain` names (about 5 ms; cache if the hook budget needs it).

Done when: each item has a red-first test, the suite is green, the latency numbers are in the ticket, and `settings sync --dry-run` shows the deny rules.

## Size, persona and model decision
One engineer on opus (ordinary implementation; the enforcement logic itself is unchanged, and SPD-008's tests guard it).
