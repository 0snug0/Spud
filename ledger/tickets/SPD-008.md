# SPD-008 — Enforcement hooks: Laws 3, 4, 6, 7, the path rule, the finishing rule, spawn recording

## Brief
Implement the hook table in the spike's Enforcement plan ([[SPD-006]], `docs/spikes/2026-09-12-ledger-database.md`): `PreToolUse(Agent)`, `PostToolUse(Agent)`, `SubagentStart`, `SubagentStop`, `PreToolUse(Bash)`, `PreToolUse(Write|Edit|MultiEdit|NotebookEdit)`, `SessionStart`, `Stop`, each `python3.14 -I -S $SPUD_HOME/bin/spud hook <name>`, installed into `.claude/settings.json` by `spud settings sync` together with the `permissions.allow` rule for the CLI. Enforcing hooks fail closed (exit 2 with the reason); recording hooks fail open and write a `hook.error` event afterwards. `agent_id` binds to a member through `tool_use_id`.

Two corrections from Spud's review of the spike: (1) direct database access is refused for writes only; read-only queries stay allowed, or the CLI offers `spud sql --readonly`, so the inspection path the spike promises Spud still works inside a session; (2) Spud's writable paths include `ledger/Home.md`, `ledger/Spud.md` and the `.base` files, which the Migration plan keeps hand-written.

Depends on [[SPD-007]]. Decided by Eric, 2026-09-12: both spawn-convention changes are approved, descriptions carry the team key and every spudagent spawn defaults to `run_in_background: true` (question 5); enforcement refuses from day one, including the path rule and the finishing hold (question 6). The fan-out check counts children alive at once (question 3).

Done when: each hook is installed and exercised by a headless `claude -p` run like the spike's probes; a spawn without a planned row, a spawn without a model, a spudagent `git commit`, and a write outside a member's deliverables are each refused with a reason; a child returning without a Result is held once; the ledger records every spawn with its usage.

## Size, persona and model decision
One engineer lead. **Tier override: fable instead of opus.** Reason: enforcement is security-adjacent and the failure mode is silent (a hook that fails open on a law). The lead may add a reviewer on fable (`01.01`) to attack the hooks before returning, as SPD-007 did; the brief asks for it. Spud's resolutions of the two corrections, written into the brief: direct database access is refused in Bash for everyone and inspection goes through a new `spud sql --readonly`; Spud's hand-written set is `spud.config.json`, `CLAUDE.md`, `.claude/**`, `docs/superpowers/specs/**`, `ledger/Home.md`, `ledger/Spud.md`, `ledger/*.base`, `ledger/_templates/**`. A missing database makes enforcing hooks refuse (the hooks are installed only at cutover, after `spud init`). Code on branch `worktree-spd-008-enforcement-hooks`; the live `.claude/settings.json` is not touched until cutover.
