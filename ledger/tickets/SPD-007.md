# SPD-007 — Ledger CLI v1: bin/spud (init, migrate, import, render, ticket and member commands)

## Brief
Build the one program that writes the ledger, as specified in [[SPD-006]]'s spike (`docs/spikes/2026-09-12-ledger-database.md`: Recommendation, Proposed schema, Concurrency model, Migration plan, Language recommendation). Python 3.14 stdlib only, one file `bin/spud`, invoked `python3.14 -I -S`. Scope from the spike's proposal 1: `init`, `migrate`, `backup`, `config sync`, `import`, `render`, `ticket new|move|edit|show`, `member new|log|result|block|finish`, `proposal file|decide`, `handoff add`, `report add`, `board`, `fleet`, `card`, `doctor`, `settings sync`, all with `--json`. `settings sync` also generates the two env caps in `.claude/settings.json` from `spud.config.json` (the spike's proposal 9, folded in here). WAL, `busy_timeout = 5000`, `BEGIN IMMEDIATE` on every write, column ownership checked on `--as`, limits as `count(*)` inside the insert transaction, timestamps from the clock.

Acceptance test before any cutover: import the markdown-v0 ledger into a scratch database, render it to a scratch directory, diff against the committed files until only formatting differs. Cutover (real `spud init`, `import`, `render`, one commit) is the last step and is Eric's go.

Decided by Eric, 2026-09-12: the database is `.spud/ledger.db` in this repo, gitignored (question 1); **per-project ticket prefixes** (question 2, against the spike's recommendation), so `tickets.key` is `<prefix>-<n>` with a counter per project, the prefixes live on the `projects` row (`spud.config.json`'s `tickets.prefix` and `teams.prefix` become the home project's values), and the team key follows the same rule; fan-out limits count children **alive at once** (`status IN ('planned','active')` under the parent), not children ever planned, while IDs keep counting every child ever planned (question 3); generated notes are read-only, with the hash check and `spud import --file` as designed (question 4); reports render from events and `spud report add` takes only the Next line (question 7); `synchronous = NORMAL` (question 9).

Done when: `bin/spud` passes the scratch acceptance test; `spud doctor` reports the interpreter and SQLite version; the DDL matches the spike's or every difference is written down in the ticket; nothing cut over yet.
