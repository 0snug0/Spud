- Store: SQLite, WAL, `<SPUD_HOME>/.spud/ledger.db`. Per connection: `foreign_keys = ON`, `busy_timeout = 5000`, `synchronous = NORMAL`. Every write is `BEGIN IMMEDIATE … COMMIT`, short, holding nothing else. One connection per process. Reads run outside write transactions. Backup is `wal_checkpoint(TRUNCATE)` then `VACUUM INTO .spud/backups/ledger-<stamp>.db`.
- `SPUD_HOME` resolution: the env var; else the git common dir of `bin/spud`'s real path (`Path(__file__).resolve()`, `git rev-parse --path-format=absolute --git-common-dir`); else `~/.config/spud/home`. Tests set `SPUD_HOME` to a temp dir.
- Schema: the spike's DDL, `STRICT`, with these amendments, each listed again in your Result as a written difference: (a) per-project prefixes: `projects.ticket_prefix`, `projects.team_prefix`, `tickets.number INTEGER NOT NULL`, `UNIQUE (project_id, number)`, `tickets.id` a plain surrogate, `key = ticket_prefix || '-' || printf('%03d', number)` and `team_key` likewise, the counter `max(number) + 1` per project inside the insert transaction; `spud.config.json`'s `tickets.prefix` and `teams.prefix` are the home project's values, written by `config sync`; (b) fan-out limits count children with `status IN ('planned','active')` under the parent, lineage numbers count every child ever planned; (c) the generated-file marker `<!-- generated by spud from .spud/ledger.db; edit with the spud CLI -->` goes immediately after the closing `---` of the frontmatter, never before it, because Obsidian reads properties only from a frontmatter block at byte 0; (d) anything else you must change, with the reason.
- Migrations: `PRAGMA user_version`, numbered SQL strings embedded in the file, forward only, `VACUUM INTO` backup before each; `init` is idempotent: create if absent, migrate if behind, refuse if ahead. Views and triggers dropped and recreated by every migration.
- Config: `spud.config.json` is read on every invocation for the limits (the config wins). `config sync` mirrors `naming.pool` into `name_pool` and the home project's prefixes. `settings sync` generates `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` and `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` in a `.claude/settings.json` from `limits`, preserving every other key; it takes `--path` and `--dry-run`; tests run it against a temp copy only. Never run it against this repo.
- Ownership: `--as spud | <agent_id> | SPUD-nnn/<Name>`; column ownership per the spike's matrix; a write outside the actor's columns is refused with a reason on stderr and a distinct exit code. Until [[SPD-008]] installs hooks, `--as SPUD-nnn/<Name>` is trusted by prose; say so in `--help`.
- Timestamps come from the clock only, stored ISO 8601 with seconds and local offset; rendered as the committed files have them (`created: YYYY-MM-DD`, `spawned: YYYY-MM-DDTHH:MM`, `finished: ""` when null). Imported timestamps keep what the file said; each imported row gets an `import` event with the source path.
- Events: append-only, both triggers; every mutation writes one; event kinds as the spike lists them.
- Render: each generated file written whole via temp file and `rename`; the `renders` table keeps the SHA-256; a file on disk whose hash differs from the record is a hand edit: refuse that file, write a `render` event with `data.conflict = true`, print the path; `import --file <path>` accepts the edit; `render --out <dir>` renders to another directory for the acceptance test. `Home.md`, `Spud.md`, the `.base` files and `_templates/` are never generated.
- Reports: import each `## HH:MM — title` entry of `reports/YYYY-MM-DD.md` as one `report.entry` event (body verbatim, `at` from the date and heading time); render the day file from its events; `report add` appends one entry with the clock time, a title and Spud's Next line. Automatic lines are [[SPD-011]].
- `card` prints a ticket's team tree (name, id, persona, model, status, spawned, finished, summary when present); the rendered `## Team` section keeps today's nested list form ([[SPD-010]] redesigns it). `board` and `fleet` print tables from `v_board` and `v_fleet`, with `board --brief` for [[SPD-011]]. `doctor` prints interpreter path and version, SQLite library version, `SPUD_HOME`, database path, `user_version`, journal mode, the three pragmas, and config sanity (unique pool names, integer limits), nonzero on a problem. Every command takes `--json`.
- State machines: tickets `queued → active → done`, `queued → declined`, `active → queued`; members `planned → active → done | blocked | failed`, `planned → failed`. `member new` inserts the `planned` row after the depth, fan-out and concurrency checks inside the same `BEGIN IMMEDIATE`, draws the lineage and a random unused name from `name_pool` unless `--name` is given, requires `--tier-reason` when the model is not the persona's default. `member log|result|block` are the member's. `member finish --status … --outcome … [--summary …]` is the parent's and stamps `finished_at`. `proposal file` is the member's; `proposal decide --decision absorb|decline|escalate|create` records a `proposal_decisions` row, and `create` makes a ticket with `origin = 'proposal'`. `handoff add` records a handoff. `ticket new|move|edit|show`.
